Without Docker Compose, you have to build and run each service separately

For example you first build your backend image from the Dockerfile in the backend folder using `docker build -t backend ./backend`, then run it with `docker run -p 8080:8080 backend`, and for something like a frontend using an existing image like Nginx you just run `docker run -p 3000:80 nginx:latest` (no need to build it since it already exists)

As the number of services grows, this becomes repetitive and error-prone because you need to manage multiple commands, ports, and connections manually. Docker Compose solves this problem by letting you define all your services in a single YAML file called `docker-compose.yaml`, where you describe each service, for example a backend built from a local Dockerfile and a frontend pulled from an existing image, along with their ports and configurations. Then instead of running many commands, you simply run `docker compose up`, and Docker Compose automatically builds images if needed, pulls existing images, creates a shared network so services can communicate using their names, starts all containers together, maps ports to your machine, and shows logs in one place. In short, Docker Compose is not a replacement for Docker but a higher-level tool that makes running multi-container applications simple, repeatable, and much easier to manage by turning a complex multi-step setup into a single command
